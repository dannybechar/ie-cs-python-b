# Grade 9 / Python C — Transition-Year Annual Strategy

Source of truth: [`ministry-source/python-c.pdf`](ministry-source/python-c.pdf).
Per-unit detail lives in each unit's own `strategy/unit-strategy.md` — see
[`../course-map.md`](../course-map.md) for the full list.

> This is a transition-year (תשפ"ז) strategy, based on the old Python C as
> an officially permitted alternative for Grade 9 this year. Update/replace
> this document once the official "AI + Computer Science Part C" syllabus
> is released.

## 1. Document Status and Sources

**Source of Truth:**
1. **Ministry circular, 2026/27 (תשפ"ז)** — permits the old Python B/C
   track in Grade 9 for this transition year, alongside the new programs.
2. **`python-c.pdf`** — the authority for content, performance objectives,
   teaching methods, assessment, and the 60-hour split.

**Transition-year constraint:** Python C was written for an old sequence
where Python B included, among other things, List, Tuple and Set. The new
Grade 8 program — AI + CS Part B — includes List but does not name Tuple
and Set as Core. A small pedagogical bridge is therefore built into Unit 1:
List is review; Tuple/Set get a compact introduction + immediate practice.
No hours are added beyond Unit 1's official 12. This is our adaptation to
the gap between program sequences, not a change to the Python C syllabus
itself.

## 2. Annual Framework

- Total: **60 academic hours**
- Each academic hour: **45 minutes**
- Operating structure: **30 double meetings of 90 minutes**
- 5 units, each **12 hours**: **2 theory hours + 10 practice hours**
- Total: **10 theory hours + 50 practice hours**

**Default delivery pattern** for each 12-hour unit: 2 meetings **Knowledge +
Lab**, 4 meetings **Lab + Lab** — i.e. each unit = 6 double meetings.

## 4. Pedagogical Progression

**Phase 1 – Organize Data – 12h** (Unit 1): from single lists to choosing
and using List, Tuple, Set, Dictionary, and compound structures. Focus:
**representation → algorithm**.

**Phase 2 – Organize Programs – 12h** (Unit 2): from procedural code to
class, attributes, constructor, methods, objects, encapsulation,
inheritance from Turtle. Focus: **data + behavior → object**.

**Phase 3 – Build Interaction – 24h** (Units 3–4): mouse events → keyboard
events → timer → animation → sound → games. Focus: **event → handler →
state change → visible behavior**.

**Phase 4 – Integrate & Own – 12h** (Unit 5): a student-defined project
integrating data structures, classes/objects, mouse/keyboard/timer events,
animation and/or sound as appropriate, plus planning, milestones,
debugging, documentation, presentation and reflection.

## 5. Default 90-Minute Lesson Pattern

**Knowledge + Lab meeting — first 45 minutes:**
1. Problem/need, 2. Concept, 3. Live example, 4. Predict/trace, 5. Guided
micro-task.

**Second 45 minutes:**
1. Read starter, 2. Modify, 3. Build, 4. Test, 5. Debug, 6. Explain,
7. Save/submit.

**Lab + Lab meetings** are used for longer algorithmic problems, game
construction, iterative debugging, integrated challenges, project
milestones, and assessment evidence.

## 6. Assessment Strategy

**Continuous evidence** throughout the year: read, trace, predict, modify,
implement, debug, explain, justify representation/design choices.

**Checkpoints:**
- Unit 1: Data Structures checkpoint.
- Unit 2: Classes/OOP checkpoint.
- Unit 3: Mouse Events mini-game.
- Unit 4: Keyboard/Timer mini-game.
- Unit 5: final integrated project.

All checkpoints are embedded inside the official 60-hour allocation.

## 7. Differentiation & Enrichment

**Core first** — every student must first demonstrate the official
learning outcomes.

**Good extension areas:** richer compound structures, larger algorithmic
challenges, additional classes, richer Turtle subclasses, more complex
event combinations, advanced game behavior, stronger project architecture.

**Avoid** turning enrichment into unrelated advanced Python content that
bypasses the official learning sequence.

## 8. Grade 9 Exit Profile

At the end of Grade 9, a student should be able to:

1. Choose among List, Tuple, Set and Dictionary for a concrete problem.
2. Work with simple and compound data structures.
3. Implement search/count/sum/min/max patterns over structures.
4. Derive a new structure from existing data.
5. Define a Python class with attributes, constructor and methods.
6. Create and use multiple objects.
7. Explain encapsulation at the required level.
8. Use procedural abstraction as a black-box concept.
9. Extend Turtle through inheritance with added attributes/methods.
10. Distinguish mouse events on screen vs. Turtle objects.
11. Implement click and drag handlers.
12. Implement keyboard event handlers.
13. Use timer/wait and animation in an interactive program.
14. Integrate sound where appropriate.
15. Build a complete event-driven game/application.
16. Plan an integrated project using milestones.
17. Debug iteratively without breaking earlier requirements.
18. Document code and architecture.
19. Present the project and explain algorithms, structures, classes and
    event flow.
20. Demonstrate ownership by modifying/explaining the submitted code.

## 9. Strategic Summary

**Grade 9 – Transition Year = Python C**

- 60 academic hours, 30 double lessons, 5 official units × 12h,
  10 Theory + 50 Practice.
- Each unit = 2 Knowledge blocks + 10 Practice blocks.
- Strong project/game orientation.
- Progression: **Data Structures → Classes → Mouse Events → Keyboard/Timer
  → Integrated Project**.
- The Grade 8 continuity gap in Tuple/Set is bridged inside Unit 1 without
  increasing hours.
- No AI Part C content is invented — this strategy must be reviewed when
  the official AI + CS Part C syllabus becomes available.
