# Units: layout and rules

[Table of contents](../CONTENTS.md) · [Repository home](../README.md) · [Standards](../docs/standards/README.md)

One folder per unit, `u<N>-<name>/`, in the order of the Ministry master table. The number `N` is the old program-unit number (the *file key*); meetings are named by official lesson numbers ([`docs/official-numbering.md`](../docs/official-numbering.md)).

```
units/u<N>-<name>/
  README.md              unit entry page: links to everything in the unit
  background-paper.md    teacher's technical and pedagogical background (not yet added for any unit)
  unit-plan.md           lesson sequence, minutes, status
  unit-strategy.md       the unit's official scope and meeting breakdown (kept from before the restructure)
  lessons/
    L<NN>-<slug>.md      the lesson page: the Hebrew student lab brief (source of truth)
    L<NN>-<slug>.html    generated one-file slide deck of that page
    L<NN>-<slug>/        NotebookLM deck (slides-he.pdf), live-lesson deck, paper-lab and countdown worksheets, challenge slide
  exercises/             student starter code (*_Starter.py) and data files
  assessment/            student-facing test sheets (Python A review test, Forms A and B)
  teacher/               TEACHER-ONLY: lesson notes, live problems, answer keys, teacher guides, countdown cases
    solutions/           reference solutions (*_Reference.py, *_Solution.py, live programs)
    live-steps/          the cumulative live-demo files (Live_Step1 ... Step5)
```

`NN` is the meeting number inside the unit (the second meeting of the strings block, Lessons 7.1–7.2, is `L02`).
There is no `feedback/` folder (no external reviews exist yet) and no `optional-java/` folder (this is a Python course).
`labels_standin.txt` (classification) and `ratings.csv` (recommender systems) sit in `exercises/` and also, as a copy, in `teacher/solutions/`, because the reference programs open them from their own folder.

## Rules

- **The background paper comes first.** Write or add it before drafting a unit's lessons, and link it from the unit plan, the entry page and `CONTENTS.md`. None exists yet; the entry pages say so and carry no dead links. Background papers are teacher-developed, not official publications: record version and date at the top.
- **Teacher-only files stay in `teacher/`.** Never put answers, solutions or marking notes in `lessons/`, `exercises/` or `assessment/`.
- **Markdown is the source of truth for a lesson page.** The `.html` deck is generated by [`tools/lesson-decks/build_decks.py`](../tools/lesson-decks/README.md); edit the Markdown and rebuild, never edit the HTML by hand.
- Each lesson follows the standards in [`docs/standards/`](../docs/standards/README.md) and the rules in [`CLAUDE.md`](../CLAUDE.md).
- Whenever a unit gains or changes material, update its entry page, its `unit-plan.md` and its row in [`CONTENTS.md`](../CONTENTS.md).
- Moves use `git mv` so history is kept; links are fixed in the same commit.

## Checks before you finish

Run from the repository root (Git Bash or any POSIX shell):

```
bash tools/check-structure.sh
python -I tools/check-repo.py
python tools/lesson-decks/build_decks.py --check
```

[`check-structure.sh`](../tools/check-structure.sh) checks that the relative links in the hub pages resolve, that every lesson has an HTML twin, and that anchors into each background paper exist (units without a paper are reported as `NO BACKGROUND PAPER`). Fix every `MISSING`, `NO HTML TWIN` or `NOANCHOR` line. `check-repo.py` checks that every `.py` compiles and every lesson has its notes, page and HTML twin. The last command confirms the decks are up to date.
