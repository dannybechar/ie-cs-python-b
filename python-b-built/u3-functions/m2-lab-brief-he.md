# יחידה 3.2 – פעולות

כיתה ח׳ · AI + Python B · **אותה פעולה, קלטים שונים: פרמטרים**

**קוראים ← חוזים ← מריצים ← בודקים ← מתקנים**

> [!IMPORTANT]
> פרמטר הוא שם מקומי בתוך ה-`def`. ארגומנט הוא הערך שנשלח בזימון. הם משויכים לפי סדר.

## דף עזר

```python
def greet(name):
    print("Hello", name)


greet("Dana")
greet("Omar")
```

<div dir="rtl">

- אותו גוף, תוצאה שונה — כי הפרמטר מקבל ערך אחר בכל זימון.
- שני פרמטרים ומעלה: הארגומנטים משויכים **לפי הסדר**.
- זימון עם פחות ארגומנטים ממה שנדרש ← `TypeError`.
- מוסיפים פרמטר רק כשמשהו באמת משתנה בין הזימונים.

</div>

## 1. חימום: הגוף לא מכיר את השם הזה

פתחו את `Card_Starter.py`.

```python
def show_result(name, stars):
    print(student, "has", stars, "stars")


show_result("Maya", 4)
```

הריצו וקראו את השגיאה. הפרמטר נקרא `name`, אבל הגוף פונה ל-`student`. תקנו מילה אחת.

## 2. משימה 1: show_mission(student, mission)

שורה אחת: `"<student> will complete <mission>"`. זמנו שלוש פעמים עם תלמידים ומשימות שונים. חזו את הפלט לפני שמריצים.

## 3. משימה 2: מתכננים show_card(student, level, points)

שלושה פרמטרים, שלוש שורות פלט (`Student:` / `Level:` / `Points:`). זמנו פעמיים עם ערכים שונים. תכננו על דף לפני שמקלידים: מה משתנה בין הזימונים, ובאיזה סדר תשלחו את הערכים?

## 4. משימה 3 (רפקטורינג): פעולה אחת, שלושה זימונים

החליפו את שלוש השורות האלה בפעולה **אחת**, שנקראת שלוש פעמים — אותו פלט, פחות כפילות:

```python
print("Level", 1, "needs", 10, "points")
print("Level", 2, "needs", 20, "points")
print("Level", 3, "needs", 35, "points")
```

זהו מה קבוע (הניסוח) ומה משתנה (שני המספרים) לפני שכותבים את החתימה.

## 5. ביקורת חתימה

מחליפים עם בן/בת זוג. בודקים חתימה אחת: האם השם מתאר תפקיד? האם כל פרמטר באמת משתנה בין הזימונים? האם הסדר ברור? נותנים הצעת שיפור אחת ומריצים שוב.
